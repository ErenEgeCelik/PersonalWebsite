## 1. `polymarket-microstructure`

**Description field (the one-liner under the repo name):**
> Reverse-engineering the dominant market maker on Polymarket's BTC
> 5-minute binary markets — feed identification, volatility dynamics,
> out-of-sample replication.

**Topics:** `market-microstructure` `prediction-markets` `polymarket`
`quantitative-finance` `market-making` `research`

**Files:**

```
README.md
LICENSE
paper/microstructure.md          # the whitepaper text, same as the site
notebooks/fair_value_demo.ipynb  # or scripts/fair_value_demo.py
src/fair_value.py
data/README.md
```

**`README.md` should cover, in this order:**
1. One-paragraph summary: ~84 hours of recorded order-book data; the
   dominant MM is a calibrated Brownian-probit pricer; ~6-tick
   out-of-sample replication of its quotes.
2. **The headline result is negative** — no candidate edge survived
   cost-inclusive out-of-sample testing. Say this plainly and early;
   it is the point of the work, not a caveat.
3. The fair-value model, written out:
   `fair_UP(t) = Φ((F − F₀) / (σ√τ))`, with what F, F₀, σ and τ are.
4. The two σ approximations and the implied-σ inversion.
5. What was tested and what happened to each test (a table).
6. A link back to the full write-up:
   `https://erenegecelik.com/whitepapers/polymarket-5min-microstructure`
   — *(use the vercel.app URL until the domain is attached)*.
7. A "What's not here" section: no live trading loop, no credentials,
   no venue-specific execution code.

**`src/fair_value.py`** — small, dependency-light (numpy + scipy only):
- `fair_value(F, F0, sigma, tau)` → the probit fair value
- `implied_sigma(F, F0, tau, mid)` → invert a quoted mid back to σ
- `sigma_from_realized(realized_15)` and `sigma_from_range(range_2)` —
  the two empirical approximations
- Docstrings with the formulas. No network calls, no API clients.

**`data/README.md`** — explain that the raw order-book recording is
not published (venue terms + size), describe its schema, and note that
the demo runs on synthetic data generated by the script.

## 2. `binary-market-making`

**Description field:**
> Inventory-skew derivation under CARA utility for binary markets,
> adverse-selection analysis, and empirical verdicts under realistic
> execution costs.

**Topics:** `market-making` `binary-options` `inventory-risk`
`optimal-execution` `quantitative-research`

**Files:**

```
README.md
LICENSE
paper/binary-market-making.md    # working draft — mark it as such
src/skew.py
```

**`README.md` should cover:**
1. Status line at the very top: **Working draft — the paper is in
   preparation.** Do not present it as finished.
2. The problem: quoting two-sided in a binary market where the payoff
   is bounded at 0 and 1, so inventory risk is asymmetric in a way
   that standard Avellaneda–Stoikov doesn't capture.
3. The derivation sketch: CARA utility → reservation price →
   inventory-dependent skew. Keep it to the shape of the argument;
   the full derivation lives in the paper.
4. Adverse selection: what a fill tells you about the fair value, and
   why that dominates in the last seconds before expiry.
5. The honest conclusion: the binding constraint was found to be
   **queue-priority inaccessibility, not model quality** — formalized
   as an MDP to stress-test the structural limits.
6. Link to the companion study (`polymarket-microstructure`).

**`src/skew.py`** — the inventory-skew rule as a pure function:
- `reservation_price(fair, inventory, risk_aversion, tau)`
- `optimal_spread(...)`
- Again numpy-only, no venue code, no live parameters. Use
  illustrative constants and say so in the docstring.

## 3. `reversible-sat`

**Description field:**
> Reversible-logic SAT circuits and what they imply for cryptographic
> primitives — an information-theoretic angle on complexity.

**Topics:** `reversible-computing` `sat-solver` `computational-complexity`
`information-theory` `cryptography`

**Files:**

```
README.md
LICENSE
notes/reversible-sat.md
src/toffoli.py
```

**`README.md` should cover:**
1. Status line at the top: **Early draft — exploratory, not a result.**
   This one is the least mature of the three; the README should not
   overclaim.
2. The idea: encoding SAT instances as reversible circuits, and what
   Landauer's principle says about the information erased by an
   irreversible solver.
3. Why SHA-256's compression function is an interesting target for
   this framing.
4. What is actually implemented so far (be specific and modest).
5. Open questions / what would need to be true for this to go
   anywhere.

**`src/toffoli.py`** — a small reversible-gate toolkit: Toffoli /
Fredkin gate simulation, a CNF-to-reversible-circuit encoder for
small instances, ancilla counting. Pure Python, no dependencies
beyond the stdlib if possible.
